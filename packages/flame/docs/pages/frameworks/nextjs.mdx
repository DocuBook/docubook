---
title: Next.js
description: Proxy a separate Flame deployment from Next.js, or merge Flame into a static Next.js export.
---

For a server-rendered Next.js application, deploy Flame separately and route the docs prefix to it. For a fully static Next.js export, merge both output directories. Both use the [shared Flame configuration](/docs/pages/overview#configure-flame) with `basePath: "/docs"` and the public application's URL in `baseURL`.

## Develop with Next.js

Next.js normally uses port 3000. Run `npm run docs:dev` on port 3001 in another terminal. Add these rules to the existing Next.js configuration:

```javascript:next.config.mjs
const docsOrigin = process.env.DOCS_ORIGIN ?? "http://localhost:3001";
const development = process.env.NODE_ENV === "development";

export default {
  async rewrites() {
    return {
      beforeFiles: [
        {
          source: "/docs/:path*",
          destination: `${docsOrigin}/docs/:path*`,
        },
        ...(development
          ? [{ source: "/__hmr", destination: `${docsOrigin}/__hmr` }]
          : []),
      ],
      afterFiles: [],
      fallback: [],
    };
  },
};
```

Merge the rules with any existing rewrites. `beforeFiles` gives the reserved docs prefix precedence over Next.js routes; the prefix is preserved at the upstream server. The development-only rule forwards Flame's SSE reload stream. See [Next.js rewrites](https://nextjs.org/docs/app/api-reference/config/next-config-js/rewrites).

Start Next.js with the application's usual `npm run dev`. Visit `/` and `/docs/` through `http://localhost:3000`. Reserve the docs prefix in any authentication middleware or proxy hooks as well.

## Link across the boundary

Use a standard anchor so navigation loads Flame's complete HTML:

```tsx:app/components/DocsLink.tsx
export function DocsLink() {
  return <a href="/docs/">Documentation</a>;
}
```

Keep application navigation components for Next.js routes. A docs navigation needs Flame's scripts and styles rather than a Next.js route response.

## Deploy a server-rendered application

Publish the docs workspace's `.docu/dist/` on a static host. Configure `DOCS_ORIGIN` in the **Next.js build environment** to the docs deployment's origin, for example `https://acme-docs.example`, then build Next.js normally. The config is evaluated during the build; changing this value requires rebuilding the application.

The upstream deployment must serve the artifact at its root, with docs under `/docs`. Keep Flame's `meta.baseURL` set to the public application URL. Enable extensionless HTML resolution on the upstream host so redirects to clean URLs also resolve through the proxy. Ensure deployment protection does not block requests from the application.

On Vercel, an [external rewrite](/docs/pages/deployment/vercel#separate-docs-deployment) is another place to configure this boundary. Choose one owner for the rewrite. Keep the Next.js preset and its normal output settings; `.docu/dist` is the output directory of the separate docs project.

## Deploy a static export

For an application that supports Next.js [static export](https://nextjs.org/docs/app/guides/static-exports), use `output: "export"` in the Next.js configuration and remove the runtime rewrites above. Runtime rewrites are unavailable in a static export; the host serves the merged files.

```shell
npx next build
npm run docs:build
cp -R .docu/dist/. out/
```

Publish `out/`. Keep docs routes out of the Next.js route tree, and apply the hosting guide's 404 rules. See [Vercel](/docs/pages/deployment/vercel) or [Cloudflare](/docs/pages/deployment/cloudflare).

Verify both direct URLs and navigation from the app, including a missing docs page that returns HTTP 404. Follow the [shared checks](/docs/pages/overview#develop-and-verify).
