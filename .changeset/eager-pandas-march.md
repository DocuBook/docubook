Minor release covering every change since `v2.0.3`: a configurable docs base path with subpath deployment support, plus the deploy and client-bundle fixes shipped alongside it. All linked DocuBook packages move to the same minor version.

### `@docubook/flame` — feat

- **feat(flame):** configurable docs `meta.basePath` — the URL prefix the docs are served under is now part of `docu.json` (`/docs` default, `/handbook` for a custom prefix, `""` for the deployment root). The prefix drives the docs output directory, dev and static routing, canonical/OG URLs, content-path rebasing, and the nginx `location` blocks generated by `flame deploy --docker`. `meta.baseURL` is documented as origin **plus deployment root** and is configured independently, so the prefix is no longer double-counted in canonical URLs. (#393)
- **feat(flame):** the docs root index is optional — an absent `docs/index.mdx`/`.md` no longer fails the build, leaves no index page, and removes stale output; the landing page always owns `/`. (#393)
- **feat(flame):** serve the search index and absolute assets from the dist-root tree, and collapse authored `/docs` paths at root deployments. (#393)
- **feat(flame):** normalize `meta.basePath` and resolve subpath deployment URLs — non-canonical values (`/Docs`, `/docs me`, `/docs//guide`, `/docs/../guide`) are canonicalized to one spelling and reported as build warnings, a non-string value fails fast before any output is written, and the JSON schema now constrains the field (`pattern`, `maxLength: 128`). The pathname of `meta.baseURL` becomes the deployment path that root-absolute references are built from: the `404.html` bundle assets and the search index records point under `<origin>/<repo>/…` on a GitHub Pages project site instead of the origin root. (#395)

### `@docubook/flame` — fix

- **fix(flame):** generate deploy files from the Bun CLI — `flame deploy` runs through a dynamically imported entry point, where `import.meta.main` is `false`, so the deployment never executed. The CLI now marks the command entry before importing. (#391)
- **fix(flame):** restore the sidebar and search crash caused by client bundle path resolution — Node-only helpers (`node:fs`, `node:path`, git) moved out of the module bundled into the browser into `server-utils.ts`, and pure string helpers into `base-path.ts`. Bun no longer injects a `node:path` polyfill into the client bundle. (#394)

### `@docubook/flame` — docs

- **docs(flame):** document `meta.basePath` and subpath deployments — new **Base Path & Subpaths** page (docs prefix vs. deployment root, common hosting setups, root deployments, canonicalization and verification), a `basePath` entry in the configuration reference, a **Serving Under a Subpath** section in the deployment guide, and the internal link/asset re-basing rules in **Formatting**.

### repo — chore

- **chore:** invalidate the build cache when the framework's render sources change, and fold the resolved prefix and deployment path into the cache stamp so a prefix change rebuilds every page instead of reusing HTML that points at the old location. (#393, #395)
